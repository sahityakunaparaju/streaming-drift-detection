# Phase 9 Notes — Ablation Study (Section U)

## 1. What this phase did — reframing, not a new experiment

Section U's ladder (Null -> Schema -> Statistical -> Schema+Statistical
-> Schema+Statistical+Semantic) is structurally the same progression as
Phase 7's B0-B4 baseline ladder. Phase 9 therefore does NOT run a new
experiment: `evaluation/ablation.py` reads the existing Phase 7
multi-seed outputs and re-presents them in ablation form, with the
incremental (delta) contribution of each added dimension computed
per-seed and aggregated as mean +/- std across the 10 seeds
([42, 123, 7, 11, 2024, 314, 2718, 999, 555, 777]).

Everything below is regenerated by:

```
PYTHONPATH=. python3 evaluation/ablation.py
```

which writes `results/phase9/ablation_table.csv`,
`results/phase9/subtype_delta.csv`, `results/phase9/lag.csv`,
`results/phase9/summary.json`, and `results/phase9/REPORT.md`.

## 2. Gap found and closed (no new data generated)

`results/phase7/multiseed/aggregate_subtype_recall.csv` contains
per-subtype recall only for schema / statistical / semantic / combined
(B4) — **B3 (schema+statistical) per-subtype recall was never
aggregated**. Per the task's gap rule, this was reported and closed
WITHOUT a new experiment: B3's per-subtype recall is recomputed from
the cached per-window decisions in
`results/phase7/multiseed/seed-<N>/rows.csv` (detectors were run in
Phase 7; the decisions are cached).

One correction was required during recomputation: the on-disk rows.csv
was written before `mean_shift` joined the expected-false-negative
rule, so its `expected_false_negative` column is stale (mean_shift
un-flagged). The authoritative flags come from the shared rule
(`drift_injection/flagging.py::expected_false_negative_reason`), which
is exactly what `experiments/refresh_multiseed_flags.py` joined in
when it refreshed the aggregates (24/110 flagged windows, B4 adjusted
F1 = 0.9945). ablation.py derives flags from the subtype via the same
rule. **Validation: the B4 recomputation matches the cached
aggregate_subtype_recall.csv 'combined' rows with 0 mismatches.**

**Concentration of the B3->B4 recall gain: adjusted 5.0000 / 5.0000 =
100.0% in semantic-drift subtypes; raw 5.0000 / 5.8400 = 85.6%** (the
raw remainder is variance_shift + distribution_shift, flagged
expected-FN windows that B4 recovers raw through semantic range
violations but that are excluded from adjusted metrics per the
documented aggregation limitation). definition_change is a Phase 8-only
subtype absent from the Phase 7 matrix, so it cannot contribute here;
the check covers the other four Phase 8 blind-spot subtypes.

**Agreement with Phase 8 (explicit):** the two independent experimental
designs agree. Phase 8 (isolated, purpose-built set) found semantic
recovers 50/50 cases that schema+statistical miss (Recovery = 1.0).
Phase 9 (general severity matrix, 110 windows/seed, all subtypes
together) independently shows that every unit of the B3->B4 gain sits
in the semantic-drift subtypes — the exact subtypes the statistical
channel is structurally blind to. The two boundary cases are
consistent too: domain_violation and unit_conversion, which Phase 8
EXCLUDED from the blind-spot set because the statistical detector
catches them, show zero B3->B4 gain here (B3 already at recall 1.0) —
semantic adds nothing where statistical already sees the change, and
adds everything where it cannot.

## 5. Detection lag ablation (step 4 of the task)

`results/phase9/lag.csv`. Mean/median/P95 lag per config across the 10
seeds: B0/B1/B2/B3 all 0.0 +/- 0.0. B4 mean 0.0333 +/- 0.0447
(median 0.0, p95 0.19). The ONLY nonzero lags are 5 streams, all
B4_unified, all lag=1: lag-variance_shift (seeds 11, 2024, 2718, 777)
and lag-distribution_shift (seed 11).

**Plain statement:** detection lag does not meaningfully vary in this
experimental design — every stream any config detects is flagged at
onset or one window later, and adding dimensions changes
recall/precision, not lag. B4's tiny nonzero mean is NOT delayed
detection of streams the lower rungs already detect; it comes from
streams ONLY B4 detects at all (variance/distribution-shift streams the
lower rungs never flag, recovered via semantic range violations at the
second drifted window). Lag is structurally ~0 here, so it is reported
for completeness and not interpreted further.
