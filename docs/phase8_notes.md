# Phase 8 Notes — Semantic Blind-Spot Experiment (Section T)

## 1. What this phase did

Phase 8 formalizes the Phase 7 subtype-recall finding (schema and
statistical detectors score 0.0 recall on `unit_change`,
`business_meaning_change`, `range_change`, and `allowed_domain_change`
windows while the semantic detector scores 1.0) into a rigorous,
isolated experiment with a quantified, purpose-built metric:

    Semantic Blind-Spot Recovery =
        semantic cases recovered by semantic detector
        ------------------------------------------------
        semantic cases missed by schema + statistical

Everything below is regenerated by:

```
PYTHONPATH=. python3 experiments/run_phase8.py [--seeds 42 123 7 11 2024 314 2718 999 555 777]
```

which writes `results/phase8/seed-<N>/...` (per-seed windows, ground
truth, per-case isolation + detector rows), plus the aggregate
`isolation_verification.csv`, `per_detector_recall.csv`,
`blind_spot_recovery.csv`, `summary.json`, and `REPORT.md`.

## 2. Headline result

**Semantic Blind-Spot Recovery = 1.0000 ± 0.0000 across 10 seeds**
(seed list [42, 123, 7, 11, 2024, 314, 2718, 999, 555, 777]),
computed over **50 isolated cases** (5 per seed: unit_change,
business_meaning_change, range_change, allowed_domain_change,
definition_change), where the schema and statistical detectors
combined missed **50 of 50** cases (W = 50) and the semantic detector
recovered **50 of 50** (V = 50). Pooled recovery = 1.0000.

Per-detector recall on the isolated blind-spot cases (mean ± std over
seeds):

| detector | recall |
|---|---|
| schema (B1) | 0.0000 ± 0.0000 |
| statistical (B2) | 0.0000 ± 0.0000 |
| semantic | 1.0000 ± 0.0000 |
| unified (B4) | 1.0000 ± 0.0000 |

Zero cases were excluded for contamination; the 20 control windows
(clean / normal_noise) were all NO_DRIFT across all four detectors.

## 3. Novel / non-standard metric label (explicit)

**Semantic Blind-Spot Recovery is a NOVEL, NON-STANDARD metric
purpose-built for this thesis (Section T of the research plan).** It
is not a published literature metric and is not compared against any
published baseline. It quantifies the coverage contribution of the
semantic detector over the blind spot left by the schema and
statistical detectors. This label is carried in the metric statement
in `experiments/run_phase8.py`
(`NOVEL_METRIC_STATEMENT`), in `results/phase8/summary.json`
(`metric.novel_non_standard: true`), and in
`results/phase8/REPORT.md`.

## 4. Case construction

The blind-spot set is a dedicated, purpose-built test set (NOT an
incidental slice of the Phase 7 matrix), generated per seed by
`drift_injection/phase8_generator.py`:

| subtype | feature | severity | contract change (metadata-only) |
|---|---|---|---|
| unit_change | temp | high | `unit`: celsius -> fahrenheit |
| business_meaning_change | temp | high | `business_meaning`: device_temperature -> case_temperature |
| range_change | temp | medium | `valid_range`: {0.0, 30.6} -> {0.0, 40.0} |
| allowed_domain_change | device | medium | `allowed_domain`: 3-ID list -> 2-ID list |
| definition_change | temp | high | `definition`: instantaneous_raw_sensor_value -> exponentially_weighted_moving_average_of_raw_readings |

plus two controls per seed (clean, normal_noise).

Every blind-spot window is a **raw, unmodified slice** of the primary
dataset; the drift exists only in the semantic-contract metadata
sidecar, applied to the reference contract by the same
`apply_semantic_metadata` machinery Phase 7 uses. No value is touched,
so the statistical signal is, by construction, pure sampling noise
between the 1000-row window and the 405,184-row reference — and the
harness re-verifies this per case with real numbers (section 5).

Windows are placed with the Phase 7 seed-aware construction
(`sample_non_overlapping_starts`, Section Y): per-seed window start
positions inside the fixed region **[320000, 405184)**, which is
disjoint from the Phase 7 matrix region ([0, 100000)) and lag region
([120000, 250000)). A full-scan probe of that region found no 1000-row
window reaching the statistical decision threshold (max score 0.215 <
0.25, max KS 0.371 < 0.50, max chi2 5.86), giving a wide safety margin
before isolation filtering.

## 5. Isolation verification (step 2 of the task) — with real numbers

Every blind-spot case was verified BEFORE the metric was computed.
The verification is not "the detector happened not to fire" — it is
actual measured values compared against the frozen thresholds. Over
all 50 cases across the 10 seeds:

| check | requirement (frozen) | observed range across 50 cases |
|---|---|---|
| schema comparison | 0 events (identical columns/dtypes/nullability) | **0/50** cases had any schema event |
| statistical score | < 0.25 (`decision_threshold`) | [0.1118, 0.2141] |
| max KS | < 0.50 (`ks_floor`) | [0.2198, 0.4647] |
| max PSI | < 72.0 (`psi_scale`; PSI/72 is the score component) | [8.05, 15.42] |
| max chi2 | < 32.0 (`chi2_scale`; chi2/32 is the score component) | [0.04, 5.90] |
| semantic detector | must fire (case-construction check) | fired on **50/50** |

Per-case, per-seed numbers (affected column's KS/PSI or chi2,
max-over-columns aggregates, schema event list, semantic event list,
verdict) are in `results/phase8/isolation_verification.csv` and
`results/phase8/seed-<N>/per_case.json`.

**No case was excluded** — every case was a clean semantic-only
signal. The two closest calls: max statistical score 0.2141 (seed
2024, business_meaning_change; gap to threshold 0.036) and max KS
0.4647 (seed 7, range_change; gap to floor 0.035). If a case had shown
an incidental statistical shift (score >= 0.25 or KS >= 0.50), it
would have been excluded and reported explicitly (the harness's
`excluded_cases` block) — none were.

The 20 control windows were also verified: schema identical, all
statistical scores below threshold, and semantic detectors silent.

## 6. Definition-change gap — decision taken: option (a)

The Phase 6/7 documented coverage gap (the semantic contract declares
no `definition` field, so definition changes are unobservable) is
**closed by option (a)**, per the task's Section T instructions — a
feasible computation-redefinition analog exists for the `temp` field:

1. `configs/semantic_contract.yaml`: `temp` gains
   `definition: "instantaneous_raw_sensor_value"` (the gross->net
   analog: the field's reported value is redefined to mean something
   computed differently — here, a smoothed/EWMA value — while the
   numbers themselves are untouched in the metadata-only injection).
2. `data/primary/reference_profile.json` regenerated via
   `generators/reference_profiler.py` (the profile embeds the
   contract; the diff is exactly the new field).
3. `detectors/semantic_detector.py`:
   `compare_semantic_contracts` gains a Level 2 exact-equality
   `definition_change` rule, mirroring `business_meaning_change` —
   no numeric threshold invented, consistent with the frozen
   `thresholds.yaml` semantic-section note that documents the future
   rule as exact-equality.
4. `drift_injection/phase7_generator.py` `semantic_metadata_for` /
   `apply_semantic_metadata` gain `definition_change` /
   `new_definition` handling (additive; no Phase 7 subtype is
   affected, so Phase 7 results are unchanged).

`configs/thresholds.yaml` was **not modified** (frozen). Its Phase 6
semantic-section comment describing the definition gap now describes
the pre-Phase 8 state; this extension supersedes it without touching
the frozen file.

## 9. Post-hoc verification — genuine per-seed variation (audit)

Before trusting the 1.0000 +/- 0.0000 headline, the result was
audited for the exact artifact that invalidated the original Phase 7
multi-seed sweep (injector randomness re-rolled inside FIXED window
positions -> artificial zero variance). The audit is reproducible:

```
PYTHONPATH=. python3 experiments/verify_phase8_variation.py
```

(writes `results/phase8/variation_proof.csv` and
`results/phase8/threshold_margins.csv`).

### 9.1 The generator uses the corrected seed-aware sampling

`drift_injection/phase8_generator.py` -> `build_phase8_set()` creates
`rng = np.random.default_rng(seed)` and calls
`sample_non_overlapping_starts(rng, ...)` (imported from the Phase 7
fix) to sample window START POSITIONS inside [320000, 405184). The
seed therefore selects WHERE each window sits in the dataset; the
injectors for these cases modify no values at all, so there is no
"injector re-roll" dimension to fake variation with.

### 9.2 Concrete proof — different rows, different values, per seed

Start rows (underlying dataset rows) for `business_meaning_change`
across seeds 42 / 123 / 7: **327977 / 325207 / 369869** (all five
case types differ per seed; full table in `variation_proof.csv`).
The raw window CSVs have DISTINCT md5 hashes across all 10 seeds for
every case type (no two seeds share a window), and the actual values
differ (first four temp values for business_meaning_change, seed 42:
[19.90, 23.60, 22.10, 23.60]; seed 7: [19.50, 26.80, 22.50,
19.60]; 8-20 distinct temp values per window). The data-dependent
statistical scores also vary per seed (e.g. unit_change: 0.1816 /
0.2138 / 0.1839 for seeds 42 / 123 / 7).

Critically, the METADATA sidecars (the semantic rule input) are
byte-identical across seeds for each subtype (md5-verified), and the
semantic EVENT SETS are constant per subtype (e.g.
allowed_domain_change always fires both `allowed_domain_change` and
`allowed_domain_violation`). So: constant rule input + varying data
+ constant outcomes. This is the OPPOSITE of the old artifact
(constant data, fabricated variation): here the inputs genuinely
vary and the deterministic outcome is identical.

### 9.3 Why zero variance is legitimate (mechanistic)

The semantic detector's contract rules are EXACT-EQUALITY,
rule-based comparisons on declared metadata (unit, business_meaning,
valid_range, allowed_domain, definition). Given the (constant)
metadata sidecar, a case either triggers the rule or it does not -
deterministically, with no probabilistic/threshold dependence on the
data. 50/50 firing on 50 genuinely different windows is therefore the
mechanistically expected outcome, not a sign of repeated cases. The
statistical detector, by contrast, is threshold-based on measured
KS/PSI/chi2: its SCORES genuinely vary per seed (0.11-0.21), but all
stay below the frozen decision threshold, so its NO_DRIFT outcome is
also constant. The zero variance is in the OUTCOME; the inputs vary.

### 9.4 Threshold-margin report (all 50 isolated cases)

Exact margins (full table in `results/phase8/threshold_margins.csv`):

| measure | min margin | median margin | max margin | closest case |
|---|---|---|---|---|
| statistical score vs 0.25 | 0.0359 | 0.0861 | 0.1382 | seed 999 allowed_domain_change, score 0.2141 (85.7% of the way) |
| max KS vs 0.50 | 0.0353 | 0.1655 | 0.2802 | seed 7 range_change, KS 0.4647 (92.9% of the way) |
| max PSI vs 72.0 | 56.58 | 60.20 | 63.95 | (score component max_psi/72 = 0.214) |

5 / 50 cases sit within 85% of the score threshold; 1 / 50 within
85% of the KS floor; none crossed. Plain statement on the "small
change in injected magnitude" question: these cases carry NO injected
value magnitude - the scores are pure sampling noise between the
window and the 405k-row reference, so there is no injection knob to
nudge. The observed closeness (max 85.7% / 92.9%) reflects the chosen
region's noise floor, not an injected signal; the region was selected
after a full scan showing its 85 windows peak at 0.215 / 0.371. If a
real value perturbation had been added (e.g. an actual Celsius->
Fahrenheit conversion), the statistical detector WOULD fire - which
is exactly why such cases (unit_conversion, domain_violation with new
categories) are excluded from the blind-spot set, per the isolation
criterion.

### 9.5 definition_change — one-sentence mechanism

The reference contract declares `temp.definition =
"instantaneous_raw_sensor_value"` while the injected window's
metadata sidecar declares `new_definition =
"exponentially_weighted_moving_average_of_raw_readings"` (applied to
a deep copy of the reference contract by `apply_semantic_metadata`),
so the semantic detector's exact-equality check on the `definition`
field emits `definition_change`, while the window's actual data
values - and therefore the schema and every KS/PSI/chi2 statistic -
are byte-identical to the unmodified reference slice.

### 9.6 Audit conclusion

The 50 cases are genuinely different windows per seed, and the
1.0000 +/- 0.0000 result is a real, reproducible finding of a
deterministic rule-based detector on varying inputs - not the Phase 7
fixed-placement artifact. No Phase 8 code was changed by this audit;
no threshold was touched.

## 10. Limitations / honest framing

- The recovery of 1.0000 is expected given the design: the semantic
  rules are exact-equality on declared metadata, so a metadata-only
  contract change is detected with certainty, and the isolation
  criterion (verified-zero statistical signal) guarantees the
  denominator is exactly the semantic-case set. The result is best
  read as: **on a purpose-built set of 50 verified-clean semantic
  cases, the schema and statistical detectors are blind to all of
  them and the semantic detector recovers all of them** — i.e., the
  semantic detector fully closes the blind spot left by the other two
  channels, with the statistical blindness demonstrated by measured
  KS/PSI/chi2, not by assumption.
- The metric is a coverage/contribution metric, not a detection-
  quality metric: it does not measure false positives of the semantic
  detector on this set (the 20 control windows, all NO_DRIFT, give a
  sanity check only).
