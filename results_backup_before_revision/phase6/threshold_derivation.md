## 3. Semantic Level-1 rule tuning

Contract-level checks (unit_change, range_change, allowed_domain_change, business_meaning_change) are exact-equality rules: 100% detection, no threshold needed.

The reference contract declares `device.allowed_domain` (the three Phase 1 device IDs, mirroring configs/schema_reference.yaml `allowed_values`), so the domain rules are in scope: domain_change detection = True, value-level violations fire 20/20 at all severities against the real contract.

| check | severity | result |
|---|---|---|
| range_violation | low (0.02x range) | 20/20 fired |
| range_violation | medium (0.08x range) | 20/20 fired |
| range_violation | high (0.25x range) | 20/20 fired |
| allowed_domain_violation | low (5 records) | 20/20 fired |
| allowed_domain_violation | medium (50 records) | 20/20 fired |
| allowed_domain_violation | high (200 records) | 20/20 fired |

Boundary false-positive risk (N=20): clean slices 0 FP under hard boundaries vs 0 with tolerance; 1% normal-noise slices 0 FP vs 0 with tolerance.

Full-dataset boundary scan: the declared contract ranges are marginally narrower than the dataset's own observed min/max (max relative overrun 0.000027); rows at the boundary are latent FP sources for clean windows that happen to contain them. Per column: humidity 3 rows (0.000000 rel); lpg 1 rows (0.000027 rel); smoke 1 rows (0.000003 rel); temp 234 rows (0.000000 rel).

**Decision: hard boundaries + relative tolerance band of 0.01** (fraction of each field's valid range) is sufficient. The band absorbs measurement-noise and float-representation overruns; every injected severity (low = 2x band, medium, high) still fires. Domain checks are exact-match and need no tolerance.

**Definition change:** the Level 1/Level 2 rule set implements no definition comparison and the reference contract declares no definition field (definition field declared = False). This is a **coverage gap, not a threshold gap** — no fake continuous threshold is invented. Documented rule for a future definition check: exact-equality on the declared definition string, mirroring business_meaning_change. Flagged for the Phase 8 semantic blind-spot experiment.

## 4. Schema confirmation + severity labeling

Schema drift is binary — drift iff any schema event. No threshold is needed or invented; detection is exact set comparison of columns/dtypes/nullability.

**Severity labeling (Section M, frozen in Phase 6):** detection stays binary; severity is a label per event. Frozen in `configs/thresholds.yaml -> schema.severity_labels` (mirrored in `configs/severity.yaml`) and verified against the detector output below.

Detector-vs-config verification: OK (all five event types emit the frozen labels).

## 5. Unified decision threshold (non-override path)

With binary schema/semantic scores and max-confidence overrides, the non-override path forces schema=0 and semantic=0, so unified = statistical/3 < 1/3 < 0.5. **The unified threshold 0.5 is unreachable in the non-override path** — it is arbitrary in the current encoding, not evidence-supported. The effective non-override rule is the statistical decision threshold (0.25). 0.5 is frozen as a conservative placeholder; if the unified threshold should play a functional role, Phase 7 should introduce continuous component scores.
